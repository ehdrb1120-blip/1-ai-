# 시스템 지도

이 vault에는 **성격이 다른 두 시스템**이 공존한다. 이 노트는 둘의 관계를 정의하고, 그래프에서 무엇을 잇고 무엇을 빼는지 결정한다.
vault 규칙은 [[raw-wiki-규칙]], 커맨드는 [[커맨드-사용법]], 스킬은 [[스킬-대부호]].

## 1. 두 시스템

| | **시스템 1 — LLM Wiki** | **시스템 2 — 클리핑 회사** |
|---|---|---|
| 구성 | `raw/` · `wiki/` · `CLAUDE.md` | `00~03` · `NORTH_STAR` · `PROJECTS/` · `_company/` |
| 출처 | 이번 vault 구축 작업 | 대부호 시작세트 ([[스킬-대부호]]) |
| 목적 | **검증된 지식의 축적** — 원천→정제 3레이어 | **실행 운영** — 에이전트·세션·승인 워크플로 |
| 신뢰도 | 출처 인용·모순 추적 강제 | 자동 생성물 포함, 미검증 |
| 갱신 | `/ingest` 승인 절차 | 세션마다 자동 |

**역할 분담**: 시스템 2가 **실행**하고, 그 결과 중 검증된 것만 시스템 1에 **박제**한다. 반대 방향(wiki → _company)은 없다.

### 빼낸다 (166개) — 도구·로그
- `_company/sessions/**` (88개) — 세션 로그. 휘발성이고 매 세션 늘어난다
- `_company/_agents/**` (78개) — 에이전트 config·prompt·tools. `.claude/agents`와 같은 **도구 파일**이지 지식이 아니다

**조치 (2026-07-30 적용 완료)**: 파일은 그대로 두고 `.obsidian/graph.json`의 `search` 필드에 **필터를 영구 저장**했다.

```
-path:"_company/sessions" -path:"_company/_agents" -path:"_company/00_Raw" -path:"_company/approvals"
```

점(`.`)으로 시작하는 폴더는 옵시디언이 자동 무시하지만, `_company`는 밑줄이라 인식된다. 폴더명을 바꾸면 시스템 2가 깨질 수 있으므로 **이름은 건드리지 않는다.**

### 유지한 설정과 이유
- `showOrphans: true` — 새 노트가 연결 안 된 상태를 **눈으로 알아채기 위해** 켜 둔다. 껐다면 편하지만 위생 신호를 잃는다
- `hideUnresolved: false` — 미작성 노트가 회색으로 보여야 **데이터 갭을 그래프에서 발견**할 수 있다. 현재 회색은 `[[마진-실적-대조]]`(의도적 갭)와 `[[2026-07-22]]`(사용자가 직접 삭제한 일간 노트) 둘뿐
- `showAttachments: false` — 이미지·영상 222건이 그래프를 덮지 않도록 유지

## 3. 모순 2건 — **해소 완료 (2026-07-30)**

두 시스템이 같은 사업을 다르게 정의하던 문제. 사용자 판단으로 통일했다.

| 항목 | 시스템 1 (구) | 시스템 2 (구) | **확정값** |
|---|---|---|---|
| 월 순수익 목표 | 300만원 | 100만원 | **100만원** |
| SNS 타깃 | 30~40대 직장인 | 20~30대 | **30~40대 직장인** |

### 확정에 따른 파급
- **손익분기가 11,500명 → 3,850명으로 내려갔다** (마진 13,000원 · 월 2회 공구). [[인스타-컨셉-평가기준]] §2 재계산 완료
- 30일 500~1,000명 목표에서 **2~4개월 안에 손익분기 도달**이 현실 경로가 됨. [[planb-log-계정전략]] §4 반영
- 300만원은 팔로워 11,500명 시점의 **다음 단계 목표**로 이관
- `_company/_shared/identity.md` 타깃 수정 완료. `goals.md`는 이미 100만원이라 변경 없음

### 반영된 파일
시스템 1 — [[인스타-컨셉-평가기준]] · [[planb-log-계정전략]]
시스템 2 — `_company/_shared/identity.md`

## 4. 중복 위험

시스템 2의 `PROJECTS/Instagram_Higgsfield.md`(573줄)와 시스템 1의 [[planb-log-계정전략]]이 **같은 주제를 각각 관리**하고 있다. 한쪽만 갱신되면 즉시 어긋난다.

**원칙**: `PROJECTS/`가 실행 계획의 원본, [[planb-log-계정전략]]은 **판정·기준 노트**. 실행 세부(릴스 원고·발행 일정)는 `PROJECTS/`에 두고, wiki는 판정 결과와 수치 기준만 유지한다.
