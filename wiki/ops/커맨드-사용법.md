# 커맨드 사용법

"어떻게 요청해야 하지?"를 매번 고민하지 않기 위한 치트시트. 규칙 자체는 [[raw-wiki-규칙]], 스킬은 [[스킬-대부호]].

## `/ingest` — raw를 wiki에 박제

가장 자주 쓴다. **입력은 경로 하나만 있으면 된다.**

| 상황 | 입력 예시 |
|---|---|
| 파일 1건 | `/ingest raw/당근마켓/Clippings/소식 - 당근비즈니스.md` |
| 여러 건을 **한 노트로 묶기** | `/ingest raw/당근마켓/Clippings/ 와 raw/당근마켓/소식글_공식.md 묶어서` |
| 폴더 통째로 | `/ingest raw/당근마켓/십채/발주서/` |
| 파일 없이 내용만 | `/ingest` 뒤에 대화·메모를 그대로 붙여넣기 |
| 인자 없이 | `/ingest` — 인덱스에 적힌 우선순위 1순위 자료를 자동 선택 |

### 경로를 몰라도 되는 표현
경로 대신 **무엇인지**만 말해도 된다.
- `/ingest 당근비즈니스 클리핑 2건 selling으로`
- `/ingest 아까 그 광고 데이터`
- `/ingest 십채 2주차 강의의 소식글 구조 부분만`

### 방향을 지시하고 싶을 때 덧붙이는 말
- `selling으로` — 영역을 지정 (분류 트리를 건너뜀)
- `개인정보 빼고` — 마스킹 요청
- `짧게` / `표 위주로` — 압축 강도
- `모호하면 그냥 물어봐` — 자동 판정 대신 확인 받기

### 결과로 나오는 것
1. 진입 판정 (통과 / 참조 / 모호 / 반려)
2. 생성된 노트 경로
3. index 갱신 항목
4. log 엔트리

**[모호]가 뜨면** 발췌 1~3문장과 선택지 2개를 제시하니, 번호만 고르면 된다.

## `/query` — wiki에서 답 찾기 (읽기 전용)

```
/query 마진 몇 %로 잡아야 해?
/query 인스타 컨셉으로 이런 게 어떨까 — {아이디어}
```
자유 문장이면 된다. wiki를 안 고치고 답만 준다.

## `/lint` — 건강 진단

```
/lint          전체
/lint sourcing 특정 영역만
```
진단만 하고 자동 수정은 안 한다.

## 서브에이전트 — 실무 작업

이름을 부르거나 일감을 말하면 된다.

| 에이전트 | 이럴 때 |
|---|---|
| `sourcing-research` | "이 제품 팔만해?", "마진 점검해줘" |
| `copy-draft` | "소식글 써줘", "상세페이지 카피" |
| `insta-plan` | "인스타 게시물 기획", "해시태그 뽑아줘" |
| `vault-keeper` | "vault 점검해줘", "미처리 raw 정리" |

산출물은 전부 `작업함/`에 초안으로 쌓인다. **wiki에 바로 안 들어가므로**, 마음에 들면 그때 `/ingest`로 올리면 된다.

## `/daebuho` — SNS 마케팅 상담

```
/daebuho 인스타 컨셉 이런 아이디어 어때?
```
[[인스타-컨셉-평가기준]]의 5축으로 판정해 준다. 자세한 건 [[스킬-대부호]].

## 알아둘 것

- **슬래시 없이 그냥 말해도 된다.** "이거 wiki에 넣어줘"라고 하면 `/ingest`와 같게 동작한다. 커맨드는 절차를 정확히 밟게 하는 장치일 뿐이다
- **`raw/`는 절대 안 고친다.** 예외가 필요하면 "raw 수정 허가"라고 명시해야 한다
- **새 커맨드·스킬이 추가되면 이 노트를 갱신한다** (CLAUDE.md §8)
