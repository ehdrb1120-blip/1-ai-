# raw→wiki 규칙 (vault 헌법)

이 문서는 추상 표현을 쓰지 않는다. 모든 판단은 아래 결정 트리와 수치 표로만 내린다.
관련: [[index]] · 영역별 실제 노트는 [[소싱-기준]](sourcing) · [[당근광고-실측]]·[[인스타-컨셉-평가기준]](marketing) · [[스킬-대부호]](ops) 참조. selling은 아직 노트 없음.

---

## §A. 진입 결정 트리 (raw 자료를 wiki에 넣을 것인가)

```
Q1. 이 자료가 아래 키워드 중 1개 이상과 직접 관련 있는가?
    [당근마켓 / 위탁판매 / 인스타 유입 / 1인 이커머스]

  NO  → Q1-a. 3개월 내 위 활동에 쓸 계획이 있는가?
              NO  → [반려]
              YES → [참조]
  YES → Q2로

Q2. 이 자료를 앞으로 2회 이상 다시 꺼내 볼 것인가?
     (1회성 잡담·중복 스샷·이미 wiki에 있는 내용 = NO)

  NO  → [반려]
  YES → Q3로

Q3. 주장·수치의 출처를 자료 안에서 특정할 수 있는가?
     (공급처명 / 날짜 / 대화 상대 / URL / 스샷 중 1개 이상)

  NO  → Q3-a. 출처는 없지만 내 직접 경험·실측인가?
              YES → [통과]  (sources: 직접작성 으로 기록)
              NO  → [모호]  → §D
  YES → Q4로

Q4. §B 결정 트리로 영역이 1개로 확정되는가?

  NO  → [모호]  → §D
  YES → [통과]
```

**4리프 정의**

| 리프 | 처리 |
|---|---|
| 통과 | 압축(§C) 후 `wiki/{영역}/` 에 신규 노트 생성 + index·log 갱신 |
| 참조 | 신규 노트 생성 안 함. 기존 노트의 `sources`에 경로만 추가 |
| 모호 | §D 절차. 사용자 답 전까지 wiki 쓰기 금지 |
| 반려 | raw/에 그대로 둠. wiki 반영 없음. log에도 기록 안 함 |

## §B. 영역 분류 결정 트리 (4분기 + 모호)

```
B1. 이 자료가 "이 제품을 팔지 말지 / 얼마에 떼올지" 판단에 쓰이는가?
    (위탁 공급처 조건, 도매 단가, 마진 계산, 경쟁 판매자 시세,
     플랫폼 내 수요 조사, 제품 후보 리스트)
  YES → area: sourcing
  NO  → B2

B2. 이 자료가 "이미 관심 있는 고객"이 보거나 나에게 말하는 것인가?
    (당근 상품 등록글, 상세페이지 카피, 제목·가격 실험 결과,
     채팅 CS 문의 원문, 응대 스크립트, 반품·환불 대화)
  YES → area: selling
  NO  → B3

B3. 이 자료가 "아직 나를 모르는 사람"을 데려오는 것인가?
    (인스타 게시물 원고, 릴스 기획, 해시태그 세트, 프로필 문구,
     인스타→당근 유입 동선, 도달·저장 지표)
  YES → area: marketing
  NO  → B4

B4. 이 자료가 판매 행위 자체가 아니라 운영·규칙·시스템인가?
    (당근 플랫폼 정책, 계정 제재 기준, 배송·정산 절차,
     세금·사업자 처리, vault 규칙, 슬래시 커맨드 사용법, 체크리스트)
  YES → area: ops
  NO  → [모호] → §D
```

**경계 사례 고정 판정 (임의 변경 금지)**

| 자료 | 영역 | 이유 |
|---|---|---|
| 경쟁사 상품글 캡처 | sourcing | 무엇을 얼마에 팔지 판단 재료 |
| 내 상품글 카피 초안 | selling | 구매 직전 고객이 보는 것 |
| 인스타 DM으로 온 구매 문의 | selling | 유입이 아니라 구매 접점 |
| 인스타 팔로워 늘리기 실험 | marketing | 아직 모르는 사람 대상 |
| 공급처와의 정산 조건 협의 | ops | 판매가 아닌 운영 절차 |
| 공급처 단가표 | sourcing | 원가 = 소싱 판단 재료 |

## §C. 압축 룰

| 항목 | 룰 |
|---|---|
| 압축률 | raw 1000줄 → wiki 100~200줄 (10~20%) |
| 노트 길이 상한 | 200줄 — 초과 시 하위 주제로 분리하고 상위 노트에서 링크 |
| 직접 인용 | raw 1자료당 ≤ 3줄 (초과분은 요약으로 대체) |
| Cross-link 최소 | 3개 — 그중 **다른 영역 노트 ≥ 1개** |
| Frontmatter | `area` `created` `sources` `tags` 4키 전부 필수. 1개라도 없으면 저장 금지 |
| 인용 없는 주장 | 금지. 수치·주장에는 출처 또는 `(추정)` 명시 |

**압축 시 버리는 것 / 남기는 것**

| 버린다 | 남긴다 |
|---|---|
| 인사말·잡담·중복 반복 | 수치(단가·마진·조회수·전환) |
| 시행착오 과정 서술 | 결론과 그 근거 1줄 |
| 원문 전체 복붙 | 재사용 가능한 문장 템플릿 |
| 스크린샷 묘사 | 스샷 경로 `raw/assets/…` 링크 |

---

## §D. 모호 처리 절차

1. 판정을 **[모호]** 로 표시하고 wiki 쓰기를 중단한다.
2. 사용자에게 다음 형식으로 제시한다.
   ```
   [모호] {자료명}
   발췌: "{raw에서 1~3문장}"
   옵션 1 — {분기 A}: {그 경우 어떻게 저장되는지 1줄}
   옵션 2 — {분기 B}: {그 경우 어떻게 저장되는지 1줄}
   ```
3. 옵션은 **정확히 2개**. 3개 이상이면 가장 가능성 낮은 것을 버린다.
4. 사용자 선택을 받은 뒤 처리하고, 아래 로그에 1줄 append 한다.
5. 같은 유형이 3회 누적되면 §B 경계 사례 표에 고정 판정으로 승격을 제안한다.

| 날짜 | 자료 | 옵션1 | 옵션2 | 사용자 선택 |
|---|---|---|---|---|
| 2026-07-29 | `소식 - 당근비즈니스` (효자장연구소 비즈프로필 화면 클리핑) | selling — 공지·소개 문구를 카피 예시로 [[소식글-구조]]에 편입 | ops — 세팅 기능·제약을 플랫폼 규칙으로 보고 별도 노트 | **옵션2 (ops)** → [[비즈프로필-세팅]] 생성 |

**판정 근거 (다음 유사 사례의 참고)**: 한 자료에 "고객이 보는 문구"와 "플랫폼 세팅 기능"이 섞여 있을 때, **그 문구가 내 것이 아니라 타 업체 것이면 카피 예시로서의 가치가 낮다**고 보고 ops로 분류했다. 내 소식글 문구였다면 selling이 맞다.
