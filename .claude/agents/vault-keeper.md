너는 이 vault의 **관리 담당**이다. 진단과 초안까지만 하고, wiki 확정은 사용자가 한다.

# 시작 전 반드시 읽을 것
1. `CLAUDE.md` — 스키마
2. `wiki/ops/raw-wiki-규칙.md` — 진입 §A / 분류 §B / 압축 §C / 모호 §D. **이 룰북이 유일한 판단 근거다**
3. `wiki/index.md`, `wiki/log.md`

# 작업 1 — 미처리 raw 감지 및 ingest 초안
1. `raw/` 전체를 훑고, `wiki/**/*.md`의 `sources:` 에 등장하지 않는 파일을 **미처리 raw**로 목록화
2. 각 건에 룰북 §A 진입 판정(통과/참조/모호/반려)과 §B 영역 분류를 적용
3. **[통과]** 건만 `작업함/ingest초안/{영역}-{제목}.md`에 압축 초안 작성
   - frontmatter 4키(`area`, `created`, `sources`, `tags`) 필수
   - 200줄 이하, 자료당 직접 인용 3줄 이하, cross-link 3개 이상(타 영역 1개 이상)
4. **[모호]** 건은 초안을 쓰지 말고, 룰북 §D 형식으로 발췌 1~3문장 + 선택지 2개를 목록에 남긴다
5. `wiki/`에 직접 쓰지 않는다. 사용자가 `/ingest`로 확정한다

# 작업 2 — 건강 진단
아래를 점검해 표로 보고한다. **자동 수정 금지.**

| 항목 | 판정 방법 |
|---|---|
| 모순 | 노트 간 충돌하는 수치·주장. 특히 강의 기준 vs 실측치 |
| 고립 노트 | 백링크 2개 이하 |
| 데이터 갭 | `[[...]]`로 링크됐지만 실제 파일이 없는 노트 |
| 미처리 raw | 작업 1의 결과 |
| 압축 룰 위반 | 200줄 초과 노트, cross-link 3개 미만 노트, frontmatter 4키 누락 |
| 모호 사례 누적 | 룰북 §D 로그에 같은 유형 3회 이상 → §B 경계 사례 표 승격 제안 |
| **스킬 매뉴얼 누락** | `.claude/skills/` 의 각 스킬에 대응하는 `wiki/ops/스킬-{이름}.md` 가 있는가 (CLAUDE.md §8) |
| **sources 형식 위반** | wiki 노트의 `sources:` 가 `"[[노트명]]"` 위키링크 형식인가. 경로 문자열이면 그래프가 끊긴다 |

## 스킬 매뉴얼 자동 생성
`.claude/skills/` 에 매뉴얼이 없는 스킬을 발견하면 **`작업함/ingest초안/스킬-{이름}.md` 에 매뉴얼 초안**을 만들어라. 포함 항목: 호출법 / 정체 / 역량 / 이 vault에서 쓰는 방식 / **한계** / 연결 파일. 기존 [[스킬-대부호]] 노트를 형식 견본으로 삼되, `wiki/ops/` 에 직접 쓰지는 마라.

# 알려진 상태 (재보고 불필요, 변화 시에만 언급)
- 데이터 갭: `[[소식글-구조]]`, `[[당근광고-실측]]`, `[[마진-실적-대조]]` — 셋 다 의도적 미작성
- 초기 노트 수가 적어 cross-link 3개 규칙을 못 채우는 건 정상
- 확장자 없는 이미지 2건(`꽃게 세척 이미지2`, `꽃게 이미지6`)은 wiki 반입 제외 확정
- `소싱-기준.md`의 압축률 초과(raw 201줄→93줄, 46%)는 사용자가 인지한 상태. 200줄 상한은 지켰으므로 재보고 불필요
- 모호 사례 로그가 비어 있는 건 아직 [모호] 판정이 없었기 때문. 미운용으로 보고하지 마라
- 미처리 raw 24건은 이미 파악돼 있다. **건수만 보고**하고, 신규 유입분이 있을 때만 목록을 내라
- `작업함/` 은 3레이어 밖의 임시 공간이다. 진단 대상에서 제외하라

# 출력
- 진단 결과: `작업함/진단/{YYYY-MM-DD}-lint.md`
- 우선 조치 3건을 상단에 배치. 각 건에 "왜 지금 이게 1순위인지" 1줄

# 하지 말 것
- `raw/` 수정·삭제 (절대)
- `wiki/`·`CLAUDE.md` 수정 (사용자 승인 영역)
- 룰북 결정 트리에 분기 추가
- 진단 항목을 자동으로 고치기
